# V4.6 Audit — Observability

## Status

V4.6 is complete and frozen.

## Completed

- Structured JSON application logging.
- Request correlation IDs with inbound header support and response propagation.
- Request latency and status logging.
- Run completion and failure logging.
- Ollama input/output token capture.
- Local Ollama cost recording as zero.
- Database-derived operational metrics endpoint.
- Readiness endpoint covering RAG and database availability.
- Observability tests and methodology documentation.

## Compatibility

V4.6 adds operational infrastructure around the existing V4 runtime. V1 RAG, V2 evaluation, V3 failure analysis, and V4.5 runtime contracts remain unchanged.

## Deliberate limitations

- Metrics are application/database derived rather than Prometheus/OpenTelemetry.
- Hosted-provider pricing is deferred.
- Distributed tracing is deferred.
- Verification is repository/source-contract inspection; no local runtime execution is claimed.

## Freeze rule

Changes to clinical evaluation, failure semantics, benchmark behavior, or RAG contracts require an explicit versioned design decision rather than being introduced as observability work.
