# V4.7 Audit — Frontend Integration

**Status:** COMPLETE AND FROZEN  
**Date:** 2026-10-04

## Result

V4.7 connects the existing lightweight frontend to the V4 backend without introducing a frontend framework or changing the frozen V1–V3 domain layers.

## Implemented

- FastAPI serves `app/frontend` at the application root.
- Overview consumes operational metrics and readiness.
- Clinical QA calls the live `/api/v1/qa` endpoint.
- Evidence is rendered from the QA response.
- Experiments can be created through the API.
- Benchmark questions can be executed through a persisted experiment.
- Experiment comparison consumes the comparison endpoint.
- Failure Observatory consumes live failure and summary endpoints.
- Failure filtering and failure detail remain client-side views over API data.
- API-provided text is escaped before DOM insertion.
- Same-origin serving avoids a separate CORS dependency.
- Frontend integration contract tests were added.

## Compatibility

No V1, V2, or V3 domain contracts were changed. V4 backend services remain responsible for persistence, evaluation, failure classification, and operational telemetry.

## Deliberate limitations

- No frontend framework was added.
- There is no experiment collection endpoint yet.
- Benchmark questions are entered directly instead of selected from a benchmark catalog.
- Run evidence does not claim exact retrieval scores/ranks because those are not currently persisted.
- Authentication and production access control remain outside V4.7.
- Verification is based on repository source/contract inspection; no local runtime test execution is claimed.

## Freeze

V4.7 is frozen. Further frontend changes should be driven by V4.8 deployment requirements or explicit product/design changes.
