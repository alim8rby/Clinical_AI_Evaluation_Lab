# V5.6 — Statistical Evaluation

## Goal

Add uncertainty-aware statistical comparison to controlled experiments.

V5.6 operates on question-level paired results produced by the V5.5 experiment engine.

## Statistical contract

For a metric, baseline and candidate results must contain the same question IDs.

The analysis reports:

- sample size
- baseline mean
- candidate mean
- candidate-minus-baseline mean difference
- bootstrap confidence interval
- paired standardized effect size (Cohen's dz)

Bootstrap intervals use a fixed seed and iteration count, making the calculation reproducible.

## Why paired comparisons

Each benchmark question acts as its own comparison unit. This avoids treating two model runs as independent samples when they were evaluated on the same questions.

## No composite score

Metrics remain separate.

The statistical layer does not:

- combine quality dimensions
- rank models with a hidden score
- convert clinical safety metrics into a single utility score
- declare clinical superiority

## Interpretation

A confidence interval describes uncertainty around the observed paired difference under this bootstrap procedure.

Cohen's dz describes standardized magnitude of paired differences.

Neither is a clinical-effect estimate.

## Limitations

- Bootstrap results depend on the benchmark sample and are not a substitute for clinical validation.
- Small benchmark sizes can produce unstable intervals.
- Multiple metrics/comparisons are not adjusted for multiple testing in V5.6.
- Statistical significance testing is deliberately not presented as the primary decision criterion.
- Benchmark annotations remain engineered and not human-validated by default.

## Verification

Focused tests cover deterministic bootstrap results, paired-ID validation, metric extraction, effect-size behavior, and experiment-level comparison rendering.

No empirical experiment result is claimed until actual experiments are executed.
