# V4.10 Audit — Final Productionization Freeze

**Status:** COMPLETE AND FROZEN  
**Date:** 2026-10-04

## Audit result

V4 now provides the frozen V1–V3 domain behind a production-style application boundary and delivery path.

### API
- FastAPI application under `/api/v1`.
- Structured error responses.
- Health and readiness endpoints.
- QA, experiment, run, evidence, comparison, report, failure, and metrics routes.
- Typed request/response schemas.
- Same-origin frontend serving.

### Persistence
- PostgreSQL target with SQLAlchemy repositories.
- Idempotent migration tracking.
- Core entity persistence.
- Failure conflict protection.
- Request-scoped failure Observatory sessions.

### Retrieval
- PostgreSQL/pgvector retrieval is used by the PostgreSQL runtime path.
- Controlled depression documents and chunks are persisted during application bootstrap.
- Deterministic 256-dimensional embeddings preserve the V1 baseline while satisfying the current pgvector schema.
- Retrieval provenance remains chunk-based and compatible with V1 evidence contracts.

### Generation
- Ollama provider with structured JSON generation.
- Provider-neutral Answer/Claim domain objects.
- Timeout and provider error handling.
- Token telemetry captured when Ollama reports it.
- Local Ollama cost recorded as zero.

### Evaluation and failure runtime
- V2 retrieval, answer, grounding, and reliability evaluators remain unchanged.
- V3 failure classification, severity, persistence, analysis, regression, and Observatory remain unchanged.
- Runtime persists runs, answers, citations, evaluations, and failures.

### Observability
- Structured JSON logging.
- Request correlation IDs.
- Request and run latency logging.
- Token and cost telemetry.
- Database-derived operational metrics.
- Readiness checks.

### Frontend
- API-backed UI with overview, QA, experiments, comparisons, and failure Observatory.
- No business logic moved into the frontend.

### Delivery
- Docker image.
- PostgreSQL + pgvector Compose stack.
- Idempotent database initialization.
- CI for compilation, tests, Ruff, mypy, Compose validation, and Docker build.
- Manual GHCR image publishing workflow.
- Immutable commit-SHA image tags.
- Runtime secrets supplied by deployment environment.

### Compatibility
No V1–V3 domain semantics were intentionally redefined. V4 adds infrastructure adapters around the frozen contracts.

## Known limitations

- The benchmark remains eight depression questions.
- The controlled corpus remains compact.
- Answer and grounding evaluation remain token-overlap baselines.
- Reliability and failure classification remain heuristic and are not clinically validated.
- The production retrieval embedding is still the deterministic 256-dimensional baseline, not a semantic clinical embedding model.
- Hosted cloud deployment, managed PostgreSQL, and external monitoring are not provisioned.
- No real patient data or autonomous clinical decision-making is supported.

## Verification

Repository inspection and GitHub Actions are used for verification. No claim of local Docker/Ollama execution is made from this audit.

## Freeze

V4.0–V4.10 are complete and frozen. Future work should be treated as a new phase rather than incremental V4 scope expansion.
