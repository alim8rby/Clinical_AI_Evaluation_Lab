# V4.6 — Observability

V4.6 adds operational visibility without changing the frozen clinical domain contracts.

## Request telemetry

Every HTTP request gets a correlation ID.

- Accepts `X-Correlation-ID` from callers.
- Generates one when absent.
- Returns the ID in the response header.
- Logs request completion with status and latency.
- Unhandled failures are logged with the same correlation context.

Logs are structured JSON and include:

- timestamp
- level
- logger
- correlation ID
- request/run identifiers when available
- latency
- token counts
- cost
- status code

## Run telemetry

Completed runs record provider usage when available.

The Ollama provider exposes only normalized usage values:

- input tokens
- output tokens
- local cost

Provider-specific response objects never enter the domain models.

Failed runs are persisted and logged with run, experiment, question, and latency context.

## Operational metrics

`GET /api/v1/metrics` reports:

- total runs
- completed runs
- failed runs
- total failures
- average run latency
- total input tokens
- total output tokens
- total recorded cost

## Readiness

`GET /health/readiness` checks:

- RAG service availability
- database connectivity

It returns HTTP 200 when both are ready and HTTP 503 otherwise.

## Limitations

- Metrics are database-derived rather than a Prometheus/OpenTelemetry implementation.
- Ollama local inference has zero recorded monetary cost; hosted-provider pricing is deferred.
- Full distributed tracing is deferred.
- Verification remains source/contract inspection unless the local application is explicitly executed.
