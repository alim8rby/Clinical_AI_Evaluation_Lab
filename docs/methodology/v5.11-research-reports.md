# V5.11 — Research Reports

## Purpose

V5.11 turns the existing experiment report data into a durable, inspectable research artifact without changing evaluation semantics.

## Artifact

The Markdown report contains:

- experiment identity and benchmark;
- completed-run count;
- reproducibility hash;
- model, embedding, retriever, prompt, evaluator, benchmark, and runtime versions;
- provider configuration;
- aggregate evaluation metrics;
- failure-category counts;
- methodology statement;
- explicit engineering limitations.

The report renderer is deterministic for the same experiment and result inputs. It intentionally excludes generation timestamps.

## API

Added:

- `GET /api/v1/experiments/{experiment_id}/report/markdown`

The existing JSON report endpoint remains unchanged and is the source of the rendered artifact.

## UX

The selected experiment view now exposes an **Open Markdown report** action.

## Interpretation boundary

The report presents engineering evaluation signals only. It does not convert them into clinical validation, safety certification, or clinical-superiority claims.

## Limitations

- Reports summarize existing aggregate data; they do not add statistical analysis.
- Failure counts are descriptive and inherit the limitations of the frozen failure classifier.
- Historical experiments may contain V5.9 compatibility values such as `unspecified`.
- Model output can remain nondeterministic even when configuration identity is fixed.
