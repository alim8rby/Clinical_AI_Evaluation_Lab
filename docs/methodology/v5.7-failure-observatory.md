# V5.7 — Failure Observatory 2.0

## Goal

Extend the V3/V4 Failure Observatory from record-level inspection to experiment-aware failure analysis.

## Design

The frozen Failure record remains unchanged.

Experiment identity is recovered through:

Failure.run_id -> RunRecord.experiment_id

Question metadata is supplied separately from the versioned benchmark:

Failure.question_id -> benchmark metadata

This avoids breaking the V3 failure schema.

## Analysis dimensions

Failures can now be analyzed by:

- experiment
- category
- failure type
- severity
- benchmark difficulty
- benchmark question type

The observatory reports failure counts, unique affected questions, completed-question denominators, and denominator-aware failure rates.

## Regression detection

Two experiments can be compared using category/type failure rates:

failure rate = failures in category/type / completed benchmark questions

The candidate rate minus baseline rate is reported.

A configurable default threshold of 0.10 marks a positive difference as a regression signal; this is 10 percentage points, not 10 percent. Question-level regression is also exposed when candidate-affected questions were not affected in the baseline.

This is an engineering regression signal, not a clinical safety threshold.

## Existing taxonomy

V5.7 does not change:

- failure categories
- failure types
- severity semantics
- classifier versions
- failure persistence schema

It enriches analysis at the read boundary.

## Limitations

- Failure rates depend on the benchmark question set.
- One question can generate multiple failure records.
- The regression signal is descriptive and threshold-based.
- It does not establish statistical significance; V5.6 provides the statistical comparison layer for suitable numeric metrics.
- Benchmark difficulty and question-type metadata are only as reliable as the benchmark annotations.
- The existing API/UI failure inventory remains intact; V5.7 adds experiment analysis, denominator-aware rates, and baseline/candidate regression views.

## Verification

Focused tests cover experiment enrichment from run mappings, difficulty/question-type analysis, deterministic dimension summaries, baseline/candidate failure-rate comparison, and explicit regression threshold behavior.

No empirical regression claim is made without actual experiment data.
