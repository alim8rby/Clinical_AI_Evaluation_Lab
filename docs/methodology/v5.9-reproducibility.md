# V5.9 — Reproducible Model Configuration

Status: **ENGINEERING COMPLETE**

## Purpose

V5.9 makes an experiment's execution identity explicit and inspectable. An experiment records the versions that determine how its evaluation was produced.

## Reproducibility dimensions

Each experiment snapshot contains:

- model version;
- embedding version;
- retriever version;
- prompt version;
- evaluator versions;
- benchmark version;
- CAIEL runtime version;
- reproducibility schema version.

The existing provider configuration dictionaries remain intact. Version fields are explicit alongside them.

## Canonical identity

The reproducibility snapshot is serialized deterministically and hashed with SHA-256.

The experiment ID incorporates the canonical snapshot, so changing a reproducibility dimension produces a different experiment identity.

## Immutability

Persisted experiment configuration is write-once. Reusing an existing experiment ID with a different configuration or reproducibility hash raises an error instead of silently overwriting the original configuration.

## API

Experiment creation accepts explicit reproducibility versions. Provider versions can be derived from the supplied model/embedding configuration when omitted.

Experiment reads expose the reproducibility snapshot and reproducibility hash.

Experiment reports include the same snapshot.

## Migration

Migration 005 adds the persisted snapshot and canonical hash.

## Limitations

- Existing experiments created before V5.9 may have incomplete historical version metadata until they are rewritten through the repository.
- "Unspecified" is retained as an explicit value where the source configuration does not identify a version; this is visible rather than inferred.
- Configuration identity does not guarantee bit-for-bit model output reproducibility when the underlying provider is nondeterministic.
- No empirical reproducibility result is claimed by this phase.
