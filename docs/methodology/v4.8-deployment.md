# V4.8 — Containerization & Local Deployment

## Goal

Make CAIEL reproducible as a local multi-service application without changing the frozen domain layers.

## Stack

- API: Python + FastAPI in the repository Docker image.
- Database: PostgreSQL 16 with pgvector.
- Models: Ollama remains a host-side service and is reached from the API container through host.docker.internal.

## Startup

The API image runs `scripts/init_db.py` before Uvicorn starts.

Database initialization is idempotent through a `schema_migrations` table. The existing SQL migrations are applied in order and recorded after successful execution.

## Compose services

`docker compose up --build` starts:

1. `db` — PostgreSQL + pgvector with a persistent named volume.
2. `api` — CAIEL application, exposed on port 8000.

The database has a PostgreSQL readiness check. The API has an HTTP readiness check against `/health/readiness`.

## Environment

`.env.example` documents the production-style database URL and Ollama settings.

The Compose deployment intentionally does not run Ollama inside the stack. This avoids coupling the application image to model storage and GPU configuration. The host Ollama service must be running and expose the configured models.

## Verification

Deployment configuration tests verify the Dockerfile, Compose services, health checks, host Ollama bridge, and idempotent database initialization.

No local Docker build or container runtime execution is claimed as part of this repository change.
