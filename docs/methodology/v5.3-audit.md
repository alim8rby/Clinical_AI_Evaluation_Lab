# V5.3 Audit — Retrieval Research Layer

Status: **ENGINEERING COMPLETE**

## Scope completed

- Dense retrieval research baseline
- Deterministic BM25 retriever
- Hybrid dense + BM25 retriever
- Shared retrieval research protocol
- ClinicalQA-v2 evaluation support
- Precision@K, Recall@K, MRR, nDCG, and latency measurements
- Strategy aggregation and comparison report
- Deterministic ranking tie-breaks
- Unit and integration test coverage
- Production V4 retrieval path unchanged
- Methodology and limitations documented

## Controlled experiment boundary

All strategies use the same benchmark, controlled corpus, expected evidence, and top-k for a valid comparison.

The dense research baseline uses the deterministic hashed embedding so the comparison does not silently mix embedding models.

## Verification

Repository inspection completed.

Focused local execution could not be performed because the current execution environment cannot resolve GitHub's network endpoint. This is independent of the repository implementation.

No empirical retrieval-performance claim is made from an unexecuted run.

## Limitations

- Compact depression-only corpus
- Dense research baseline is not semantic embedding retrieval
- Latency is environment-dependent
- No reranker in V5.3
- Retrieval metrics depend on benchmark evidence annotations

## Freeze decision

The V5.3 engineering layer is complete. Future empirical retrieval results must be produced by running the controlled research experiment and should be stored separately from the implementation freeze.
