# V5.4 — Generation Evaluation Layer

## Goal

Make generation configuration a controlled experimental variable while holding the benchmark and retrieved evidence constant.

V5.4 evaluates generation providers through a common research contract.

For each question/provider pair it records:

- answer correctness
- answer completeness
- answer relevance
- grounding/faithfulness
- unsupported claim rate
- hallucination rate
- uncertainty handling
- generation latency
- input tokens
- output tokens
- cost

The existing lexical and semantic evaluators are reused rather than replaced.

## Experimental control

A generation comparison keeps these conditions explicit:

- benchmark version
- question set
- evidence set per question
- prompt version
- evaluator
- provider configuration

Only the generation provider/model should vary in a model comparison. This prevents retrieval differences from being incorrectly attributed to generation quality.

## Research API

The research layer provides case evaluation, strategy summarization, and cross-provider comparison.

Providers implement the existing provider contract and can expose last_usage for operational comparison.

The comparison output contains one summary per provider and does not create a hidden composite quality score.

## Metrics

Quality:
- correctness
- completeness
- relevance

Grounding:
- faithfulness
- unsupported claim rate

Reliability:
- hallucination rate
- uncertainty handling

Operations:
- latency
- input tokens
- output tokens
- cost

Semantic scores remain available through the existing semantic evaluator boundary.

## Methodological boundary

This layer does not claim that any model is clinically correct. Model-assisted semantic evaluation is an evaluator signal, not clinical ground truth.

The research layer does not modify the V4 production runtime.

## Limitations

- Actual model comparisons require a runnable provider environment.
- Local Ollama model performance is environment/model dependent.
- Cost is provider-reported; the local Ollama provider currently reports zero cost.
- Latency is environment-dependent.
- Reliability signals remain heuristic.
- Human calibration remains optional and has no labels in the repository by default.

## Verification status

The implementation is verified by repository inspection and focused test coverage. No empirical model-performance claim is made until a controlled benchmark run is actually executed.

## Freeze boundary

V5.4 engineering is complete when multiple generation providers/configurations can be evaluated under one contract, benchmark and evidence conditions remain fixed, quality/grounding/reliability/operational metrics are comparable, raw question-level results are preserved, tests cover evaluation and comparison, and production runtime remains unchanged.
