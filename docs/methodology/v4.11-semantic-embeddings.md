# V4.11 Semantic Embeddings

V4.11 replaces the production PostgreSQL retrieval embedding baseline with Ollama `nomic-embed-text`.

## Design

- `OllamaEmbeddingProvider` implements the existing `EmbeddingProvider` contract.
- PostgreSQL stores semantic vectors separately from the frozen 256-dimensional V1 baseline.
- Migration 003 adds a 768-dimensional `semantic_embedding` column and HNSW cosine index.
- The PostgreSQL runtime indexes and queries `semantic_embedding`.
- The deterministic hashed provider remains available for development and compatibility.
- Provider-specific HTTP types do not cross into the retrieval domain.

## Re-indexing

Migration 003 does not convert old hashed vectors. The controlled corpus is re-ingested by the application bootstrap so each chunk receives a fresh semantic embedding.

## Limitation

The chosen embedding dimension is tied to the configured `nomic-embed-text` model. A different embedding model requires a dimension-aligned migration and re-indexing before use.

## Freeze

V4.11 changes retrieval representation only. Evaluation, failure analysis, API contracts, and V1–V3 domain semantics remain unchanged.
