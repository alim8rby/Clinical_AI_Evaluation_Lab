# V4.7 — Frontend Integration

## Goal

Replace the V3 static Failure Observatory fixture with a lightweight frontend backed by the V4 API.

## Scope

The frontend provides five connected views: Overview, Clinical QA, Experiments, Comparison, and Failure Observatory. The V3 failure presentation is preserved conceptually, but its data source is now the API.

## API integration

The browser uses same-origin requests to `/api/v1/metrics`, `/api/v1/qa`, `/api/v1/experiments`, `/api/v1/experiments/{id}/runs`, `/api/v1/comparisons`, `/api/v1/failures`, `/api/v1/failures/summary`, and `/health/readiness`. FastAPI serves `app/frontend` at the root path, so no CORS configuration is required.

## Constraints

- No frontend framework was introduced.
- Business logic remains in the backend.
- The browser consumes API contracts rather than repositories or domain internals.
- API-provided text is escaped before insertion into the DOM.
- V1–V3 domain contracts remain unchanged.

## Known limitations

- There is no experiment collection endpoint yet, so the UI retains experiment IDs created during the current session.
- Benchmark questions are entered directly rather than selected from a benchmark catalog.
- Run evidence reflects persisted cited chunks and does not claim exact retrieval scores/ranks.
- Authentication and production access control remain outside V4.7.
