# V5.10 — Platform UX

## Purpose

V5.10 improves the existing CAIEL frontend as an evaluation workflow rather than adding new evaluation logic.

## Scope

- Experiment discovery through a read-only experiment library.
- Selection of an experiment as the active workflow context.
- Direct inspection of experiment reproducibility identity and aggregate metrics.
- Comparison workflow prefilled from the selected experiment.
- Existing failure analysis and Evidence Explorer remain the investigation surfaces.

## API

Added:

- `GET /api/v1/experiments`

The endpoint returns the existing `ExperimentResponse` contract for each experiment. No evaluation or persistence contract was changed.

## UX flow

1. Open Experiments.
2. Refresh or load recent experiments.
3. Select an experiment.
4. Inspect configuration identity, reproducibility hash, and available metrics.
5. Run questions against the selected experiment.
6. Use the selected experiment as the comparison baseline.
7. Move to Failure Observatory for failure analysis and Evidence Explorer for per-run trace inspection.

## Design constraints

- Existing backend evaluation semantics are unchanged.
- No new composite score is introduced.
- No clinical interpretation is added.
- The frontend remains intentionally minimal.
- Reproducibility snapshots are displayed, not modified.

## Verification

Frontend JavaScript syntax and referenced DOM IDs were statically checked after implementation.

Runtime/API tests were not executed in this phase. GitHub Actions remains informational because of the repository's known CI-environment failure mode.

## Limitations

- The experiment library is not paginated.
- Metric exploration is aggregate and uses the existing report endpoint.
- Historical experiments may expose V5.9 compatibility defaults where a reproducibility snapshot was not stored.
